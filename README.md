# Тестовое задание: системный аналитик по данным

## Цель

Спроектировать и реализовать прототип хранилища данных на основе Lakehouse-архитектуры (Trino, Apache Iceberg, MinIO): выполнить задачи тестового задания и описать системную архитектуру решения.

## Задачи

1. Стенд развёрнут в Docker на основе репозитория [maxalyapyshev/trino-iceberg-minio](https://github.com/maxalyapyshev/trino-iceberg-minio).

**Состав:** MinIO (S3-хранилище), mc (инициализация bucket `warehouse`), Iceberg REST Catalog и Trino.

**Доступ:**

| Сервис | Адрес |
|---|---|
| MinIO UI | http://localhost:9001/ |
| Trino UI | http://localhost:8080/ |

**Запуск:**

```bash
docker compose down && docker compose up -d
```

- Образы MinIO и mc собираются из исходников, если локальных образов нет.
- Параметры заданы в Compose по умолчанию. Чтобы изменить их, скопируйте `.env.example` в `.env` и отредактируйте.
- Данные MinIO хранятся в томе `minio_data`. Команда `docker compose down -v` удаляет том вместе с данными.

**Ресурсы VPS:** 2 ядра CPU, 6 ГБ памяти, 15 ГБ диска.

2. Подготовить данные TPC-H. Кратко описать таблицы, ключи, связи и гранулярность. Объём данных выбрать самостоятельно.
3. Спроектировать и реализовать центральный слой Data Vault 2.0.
4. Построить 1–2 витрины данных на базе центрального слоя. Определить бизнес-вопросы, гранулярность и правила расчёта показателей.
5. Автоматизировать загрузку слоёв хранилища. Показать первичную и повторную загрузку, обработку изменений без дублей.
6. Реализовать несколько проверок качества данных. Описать проверяемые правила и приложить результаты запуска.
7. Опционально: развернуть Apache Superset в Docker и создать дашборд на основе витрин.

## Примечания
1.	Можно пользоваться любыми средствами, включая LLM.
2.	Срок исполнения не регламентируется, а учитывается при оценке. Однако, качество работы ценится гораздо выше скорости исполнения.
